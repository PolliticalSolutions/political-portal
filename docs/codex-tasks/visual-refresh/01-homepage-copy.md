# Task 01: Approve homepage and shared-shell copy

Follow `00-shared-rules.md`.

## Objective

Create an approval-ready copy specification for the homepage, public navigation, and public footer. Do not edit application code, CSS, assets, routes, or metadata.

## Sources to inspect

- `src/pages/Home.jsx`
- Public portions of `src/App.jsx`
- `src/components/Footer.jsx`
- `POLITICAL_SOLUTIONS_CONTEXT.md`
- The Brand folder's `README - Logo usage.md` and `website-handover/POLITICAL_SOLUTIONS_DESIGN_SYSTEM.md`

## Requirements

- Write in authoritative, direct, grounded British English.
- Use **Political Solutions** as the public name. Never use **Political Solutions Ltd**.
- Do not copy the design-mockup wording automatically. Treat it as a direction requiring editorial judgement.
- Do not invent capabilities, delivery history, customer claims, prices, statistics, or founder credentials. Cite the repository source for every substantive claim; list anything unverified as a question.
- Establish one primary homepage action and one clearly secondary action.
- Cover: navigation labels, hero, product choice, product-proof section, experience/proof, process, closing CTA, footer, homepage title, and meta description.
- Keep the three products distinct without presenting incomplete portal functionality as available.

## Deliverable

Create `docs/public-site-copy/01-homepage-and-shell.md` containing:

1. Page objective and audience.
2. Exact proposed copy, mapped to each section and CTA.
3. Claim/source table.
4. Removed or rejected wording with a short reason.
5. Unresolved factual questions.
6. Status: `DRAFT — USER APPROVAL REQUIRED`.

## Verification

- Pass 1: compare every proposed claim and link label with repository evidence and current routes.
- Pass 2: cold editorial review for clarity, duplication, British English, CTA hierarchy, banned startup language, and unsupported claims.

Stop and ask the user to approve or amend the copy. Do not implement it.
